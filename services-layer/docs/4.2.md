**4.2. Estudo da integração com o ERP Jasmin**

**4.2.1. Enquadramento**

Durante a análise das soluções ERP para o projeto de Gestão Inteligente de Assistência Técnica e Intervenções, foi considerada a plataforma Jasmin como uma alternativa para a integração dos processos comerciais e administrativos.

O objetivo deste estudo consistiu em avaliar a possibilidade de utilizar a API do Jasmin para gerir informações relacionadas com clientes, artigos, existências e documentos comerciais, estabelecendo uma ligação com a aplicação desenvolvida em Mendix.

Ao contrário do Moloni ON, que utiliza uma API GraphQL, o Jasmin disponibiliza uma API REST, permitindo realizar operações de consulta, criação e atualização de recursos através de pedidos HTTP e troca de dados em formato JSON.

A análise centrou-se nos mecanismos de comunicação, autenticação e adaptação dos serviços, de modo a avaliar a possibilidade de reutilizar a arquitetura intermédia definida para o projeto.

**4.2.2. Abordagem de integração**

A abordagem considerada para o Jasmin baseava-se na utilização da sua Web API REST, através de pedidos HTTPS e respostas em formato JSON.

A documentação técnica apresenta uma estrutura de URLs que identifica a conta, a subscrição, o módulo funcional e o recurso pretendido, seguindo o formato:

https://my.jasminsoftware.com/api/{account}/{subscription}/{module}/{resource}

Para permitir o acesso à API, seria necessário registar uma aplicação no ecossistema Primavera, configurar o mecanismo de autenticação e obter as credenciais e autorizações adequadas.

A autenticação é baseada no protocolo OAuth 2.0, através do serviço Primavera Identity, permitindo obter tokens de acesso para a execução dos pedidos.

Na arquitetura proposta, a Services Layer poderia funcionar como intermediária entre o Mendix e o Jasmin, ficando responsável pela gestão dos tokens, execução dos pedidos REST, transformação dos dados e tratamento dos erros devolvidos pelo ERP.

**Operações consideradas para a integração**

| **Área funcional** | **Operação pretendida** |
|---|---|
| Clientes | Pesquisar clientes por NIF e criar novas fichas |
| Artigos | Consultar produtos, serviços e respetivos preços |
| Stock | Consultar existências dos artigos |
| Faturação | Criar e consultar documentos comerciais |
| Documentos | Obter representações de faturas para envio ao cliente |
| Pagamentos | Consultar ou registar documentos associados à liquidação |

Estas operações representam os requisitos funcionais que teriam de ser mapeados para os recursos concretos disponibilizados pela API Jasmin. A disponibilidade e os parâmetros exatos de cada operação dependeriam da análise específica dos respetivos endpoints.

A documentação disponibiliza referências técnicas e coleções Postman que poderiam apoiar a exploração e os testes da API.

Não foi identificada, no âmbito desta análise, uma camada de integração REST previamente desenvolvida que correspondesse integralmente ao contrato definido para a aplicação Mendix.

Assim, a utilização do Jasmin exigiria a implementação de um adaptador próprio, responsável por converter as operações internas da Services Layer nas chamadas específicas da API do ERP.

Este adaptador permitiria preservar a interface REST apresentada ao Mendix, alterando apenas a implementação da comunicação com o sistema comercial.

Contudo, esta possibilidade permaneceu ao nível de estudo técnico. Não foi implementado um adaptador para o Jasmin nem foram validadas operações reais através da sua API no âmbito da presente fase do projeto.

**4.2.3. Decisão tecnológica**

Após a análise das alternativas, o grupo optou por utilizar o Moloni ON como ERP principal da solução.

Esta decisão permitiu concentrar o desenvolvimento e a validação numa única plataforma, reduzindo a complexidade associada à implementação simultânea de integrações com diferentes sistemas comerciais.

A escolha possibilitou a implementação de uma Services Layer funcional em Node.js e Express, com autenticação, documentação OpenAPI e endpoints REST de consulta de produtos, clientes e stock.

Foi igualmente realizada uma prova de conceito de faturação, com criação e consulta de uma fatura em rascunho através da API GraphQL do Moloni ON.

O Jasmin permaneceu, assim, como alternativa tecnológica estudada, sem implementação prática nesta fase. A comparação das características dos dois sistemas é apresentada na Secção 3.2, dedicada à análise do ERP Jasmin.

**4.2.4. Síntese**

O estudo da integração com o Jasmin contribuiu para compreender uma abordagem alternativa de comunicação com sistemas ERP, baseada em APIs REST e mecanismos de autenticação OAuth 2.0.

A análise permitiu identificar os principais requisitos técnicos para uma eventual integração, nomeadamente o registo da aplicação, a gestão de tokens, a identificação dos recursos disponíveis e a adaptação dos modelos de dados.

Apesar de não ter sido implementado um adaptador Jasmin, a separação de responsabilidades estabelecida na arquitetura da solução permitiria, conceptualmente, incorporar outros sistemas ERP através do desenvolvimento de módulos de integração específicos.

Nesta fase, o desenvolvimento prosseguiu com o Moloni ON, mantendo o estudo do Jasmin como referência para uma eventual evolução futura da solução.
